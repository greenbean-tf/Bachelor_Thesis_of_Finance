# Formation Table 產生程式：跨平台結果不一致問題與解決方案

## 一、背景

為了驗證 formation table 產生程式（`create_formationtable.py`／`mt.py`，內容為逐配對計算VAR模型定階、Johansen共整合檢定與VECM參數估計）在 Google Colab 上執行的結果是否跟原本在本機 Windows 上執行的結果一致，用同一批分鐘股價資料在兩個平台上各跑一次，並逐配對比對輸出的`Johansen intercept`、`Johansen slope`、`Johansen std`、`W1`、`W2`、`VECM_q`、`Model`。

## 二、觀察到的現象

比對結果顯示：**`VECM_q`與`Model`（落後期數與最適模型選擇）在兩平台上永遠完全一致**，但**`Johansen intercept`、`Johansen slope`、`W1`、`W2`在部分配對上出現明顯差異**（約佔各檔案配對數的0.2%~1.2%），且差異幅度不是浮點誤差等級的微小雜訊，而是相當大的數值（例如intercept差異可達10以上，W1/W2差異可接近2.0，遠超過合理的浮點誤差範圍）。

## 三、根本原因：廣義特徵向量的符號不唯一

`mt.py`裡`JCItestpara_spilCt()`函式透過`scipy.linalg.eigh()`解一個廣義特徵值問題（`eigh(S10·S00⁻¹·S01, S11)`）來取得共整合向量。**廣義特徵值問題的特徵向量方向不唯一**：若`v`是某特徵值對應的特徵向量，則`-v`同樣是合法解（代入原方程式兩邊同乘-1，等式依然成立）。

`scipy.linalg.eigh()`底層呼叫LAPACK函式庫，而**LAPACK規格本身並未保證特徵向量的正負號在不同實作（Windows常用Intel MKL、Colab用OpenBLAS或其他build）之間保持一致**。程式碼裡也沒有針對這個自由度做任何校正，因此同一組輸入資料，在不同平台上可能解出方向相反、但數學上同樣正確的特徵向量。

### 為什麼VECM_q / Model不受影響，intercept / slope / W1 / W2卻受影響

- `Model`的選擇是透過trace test（`JCI_AutoSelection`），統計量只依賴**特徵值**，不依賴特徵向量，因此不受符號影響。
- `Johansen intercept`、`Johansen slope`是透過`Johansen_mean()`計算，其中`alpha_hat = alpha · (αᵀα)⁻¹`只用到**單一**alpha向量（未與beta配對抵銷），因此特徵向量符號翻轉會讓`alpha_hat`翻轉，進而讓`Johansen intercept`／`slope`整個變號。
- `W1`、`W2`是`beta`正規化後的直接結果（除以絕對值總和，不會修正符號），因此beta翻轉，`W1`／`W2`就跟著翻轉。

### 實證驗證

為確認上述診斷，我們寫了一個對照實驗：人為將`eigh()`回傳的特徵向量整個取負號（模擬另一平台選到相反符號的情境），重新計算同一筆真實資料。結果顯示：**`Johansen intercept`、`slope`、`W1`、`W2`全部剛好變成原本數值的負值**，與實際觀察到的Windows/Colab差異型態（差異約為原始數值的2倍）完全吻合，證實診斷正確。

## 四、解決方案：符號校正（Sign Normalization）

由於這個差異的根源是「特徵向量符號自由度沒有被固定」，解法是在計算出特徵向量後、後續計算開始前，加入一個**確定性的符號校正規則**，讓任何平台都收斂到同一個符號：

```python
eigVecs = eigvecs[:, sort_ind]

# 用「最大絕對值分量為正」固定主特徵向量的符號
dominant_vec = eigVecs[:, 0]
sign_anchor_idx = np.argmax(np.abs(dominant_vec))
if dominant_vec[sign_anchor_idx] < 0:
    eigVecs[:, 0] = -dominant_vec

eigVecs_st = eigVecs / np.sum(np.absolute(eigVecs[:, 0][0:2]))
```

**為什麼選「最大絕對值分量為正」而不是「第一個分量為正」**：後者在該分量剛好接近0時會不穩定（極小浮點誤差就可能讓符號在正負間擺盪），前者因為錨定在向量中量值最大的分量，數值上更穩健。

同一個對照實驗（人為翻轉特徵向量符號）驗證：加入這個校正後，不管輸入的原始符號為何，最終算出的`intercept`／`slope`／`W1`／`W2`都收斂到同一組數值，跨平台差異消除。

## 五、這個修正是否改變原本估計的統計意涵？

**不會**。`β`與`-β`定義的是同一個共整合關係（`β₁y₁+β₂y₂`與`-β₁y₁-β₂y₂`是否為定態序列是等價的），符號本身沒有統計上的優劣之分。而且在後續的交易策略邏輯中，若`β`、`α`、intercept、slope、`W1`/`W2`一起同步翻轉，整體交易決策（何時做多、何時做空）在數學上是完全對稱、等價的——這個問題只影響「同一組輸入在不同次執行/不同平台間能否得到一致的數值結果」，不影響任何單一次估計本身的正確性。
